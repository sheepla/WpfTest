# WpfInspector 仕様

## 目的

WPF アプリケーションを対象に、実行中プロセスの選択、WPF 判定、自己プロセスまたは外部プロセスの UI 走査、Portable PDB 解析を 1 つの WPF ツールで実行できるようにする。

現行実装では、モジュール情報は内部で収集して PDB 候補決定に利用するが、専用のモジュール一覧 UI は持たない。

## 対象ユースケース

1. 実行中プロセス一覧から対象候補を探し、名前・PID・ウィンドウタイトル・自己プロセス判定を確認する
2. 選択プロセスの実行ファイルパス、起動時刻、ワーキングセット、モジュール数、注意事項を確認する
3. 選択中 WPF プロセスに対して初期 PDB 候補を確認し、必要なら `.pdb` / `.dll` / `.exe` を手動指定する
4. 一括解析で UI 走査を実行し、ランタイムで使われているアセンブリ候補から PDB 解析対象を再決定する
5. 走査結果としてウィンドウ一覧、UI ツリー、ランタイムアセンブリ候補を確認する
6. Portable PDB の文書一覧、メソッド一覧、シーケンスポイント集計を確認する

## 機能要件

### 1. プロセス一覧

- 実行中プロセスを名前順で一覧表示する
- プロセス名、PID、自己プロセス判定、応答状態、ウィンドウタイトルを表示する
- 既定では自己プロセスまたはウィンドウを持つプロセスを表示し、チェックボックスでバックグラウンドプロセスも表示できる
- フィルタ文字列でプロセス名、PID、ウィンドウタイトル、実行ファイルパスを部分一致検索できる
- 起動直後は `WpfInspector` 自身を優先して選択する

### 2. プロセス詳細

- 選択プロセスの実行ファイルパスを表示する
- 起動時刻、ワーキングセット、モジュール数を表示する
- WPF 判定結果と自己プロセス判定を表示する
- 実行ファイルパス取得失敗、モジュール列挙失敗、WPF バージョン、アーキテクチャなどの注意事項を表示する
- モジュール列挙結果は内部で保持するが、現行 UI では個別モジュールの一覧表示は行わない

### 3. PDB 候補決定

- 選択中 WPF の初期解析対象は、メインモジュールを基本としつつ、apphost 風の `.exe` では同名の隣接 `.dll` を優先できる
- UI 走査後は、ランタイムで実際に使われているアセンブリ候補を優先して解析対象を再決定する
- 候補が解決できない場合は、初期解析対象またはメインモジュールへフォールバックする
- `.pdb` / `.dll` / `.exe` はテキストボックス入力またはファイル参照で手動指定できる

### 4. PDB 解析

- Portable PDB を解析対象とする
- 解析結果として以下を表示する
  - 文書一覧
  - メソッド一覧
  - メソッドごとのシーケンスポイント数
  - 可視シーケンスポイント数
- アセンブリが指定されていればメソッド名を解決し、指定されていなければトークン中心で表示する
- Classic Windows PDB は未対応として扱う

### 5. WPF UI 走査

- WPF 判定済みの選択プロセスに対して一括解析を実行できる
- 一括解析では、先にランタイム UI 走査を行い、その後に走査結果から PDB 解析対象を決定する
- `WpfInspector` 自身を選択した場合は注入を行わず、アプリ内で直接走査する
- 外部プロセスを選択した場合は `WpfInspector.NativeBootstrap.dll` を注入し、`WpfInspector.TestHelper` と名前付きパイプで通信して走査する
- 走査結果として以下を表示する
  - WPF バージョン
  - Dispatcher 状態
  - ウィンドウ一覧
  - 選択ウィンドウの UI ツリー
  - ランタイムアセンブリ候補の要約
- UI 走査が完了した場合、PDB が見つからない、または解析に失敗しても、UI 走査結果は保持する

### 6. 失敗時の扱い

- 権限不足、プロセス情報取得失敗、PDB 未検出、注入タイムアウト、UI 走査失敗はアプリ全体の異常終了ではなく、ステータスまたは警告として通知する
- 外部プロセス注入前に、自プロセスと対象プロセスの権限レベルを比較し、対象の方が高い場合は実行前に中断する
- 解析中は単一のビジーフラグで多重実行を抑止する

## 現行仕様で扱わないもの

- 専用のモジュール一覧 UI
- PDB 解析結果のエクスポート
- フィルタ条件の永続化
- セッション記録と比較機能
- 注入失敗時の自動再試行
- 署名済み解析アダプタのロード

## 非機能要件

- .NET 10 / WPF ベース
- コアロジックは UI から分離し、単体テスト可能にする
- UI をブロックしないよう、重い処理は非同期で実行する
- 管理者権限がなくても取得できる情報を優先する
- 外部プロセス走査は x64 版 `WpfInspector.NativeBootstrap.dll` を前提とする

## セキュリティ境界

- DLL 注入対象は、UI 上でユーザーが選択した外部 WPF プロセスに限定する
- 外部プロセス走査では、セッションごとの一時ディレクトリへ Bootstrap / TestHelper / InspectionPayload をコピーして使用する
- 名前付きパイプ名は対象 PID とセッション ID を含む一意な名前を使用する
- `WpfInspector` 自身を選択した場合は注入を行わない

## アーキテクチャ

- `WpfInspector.App`
  - 画面表示
  - ユーザー操作
  - ViewModel
  - 一括解析のオーケストレーション
  - 権限チェックと注入前検証
- `WpfInspector.Core`
  - プロセス列挙
  - WPF 判定
  - PE / CodeView 情報読み取り
  - Portable PDB 解析
  - 解析モデル
- `WpfInspector.Injector`
  - `CreateRemoteThread + LoadLibraryW` ベースのネイティブ DLL 注入
- `WpfInspector.NativeBootstrap`
  - 注入先プロセスで `hostfxr` を使って `WpfInspector.TestHelper` をロードするネイティブブートストラップ
- `WpfInspector.TestHelper`
  - 注入先プロセス内で名前付きパイプのサーバーとなり、UI 走査コマンドを受け付けるブリッジ
- `WpfInspector.InspectionPayload`
  - WPF ウィンドウ、UI ツリー、ランタイムアセンブリ候補の収集
- `WpfInspector.LlmAgent`
  - `TestHelper` のパイププロトコルを使って対象 WPF を操作する開発補助用コンソール
